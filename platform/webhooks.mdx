Webhooks are how Bindbee tells your application that a sync finished or a record changed, instead of your application polling to find out.

## Where to find it

In the Dashboard, go to **Configure → Webhooks**.

## What you configure there

| Field | What it does |
| --- | --- |
| **Destination URL** | Where deliveries are sent. **Test URL** confirms Bindbee can reach it before you save |
| **Webhook Name** | Your own label, for finding it later |
| **Webhook Type** | Which environment's connectors this webhook covers - Development, Production, or both |
| **Events** | Which events trigger a delivery, chosen by checkbox |

The **Security** section on the same page holds your organization's signature key. Every delivery is signed with it, and your handler should verify that signature before acting on the payload - see [Validate webhook signatures](/how-to/reliability/validate-webhook-signatures).

<Warning>
  The Dashboard labels events in prose, but the payload carries the event
  string - `connector_synced`, not "Sync completed". Match on the string, and
  note that event strings use **underscores**, never hyphens. Matching the wrong
  form fails quietly: your handler simply never runs.
</Warning>
