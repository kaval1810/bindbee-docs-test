A Magic Link is a hosted URL your customer opens to authorise their HRIS. They enter their own credentials; you never handle them. When they finish, a connector appears in your account - with no front-end code on your side.

<Info>
  **Before you start**

  - You know which environment this connection belongs in - see [Environments](/how-to/setup/choose-an-environment). It's fixed at creation, though a connector can be moved later without the end user reconnecting - see [Move between environments](/how-to/setup/move-a-connector-between-environments).
  - You know which integration the customer uses - see [Integration slugs & variants](/how-to/setup/look-up-an-integration-slug).
</Info>

## Steps

<Steps>
  <Step title="Confirm the environment">
    Check the dashboard is in the environment you intend. A link generated in Development creates a Development connector.

    **Result:** You're in the right environment.
  </Step>

  <Step title="Create the link">
    Go to **Magic Link** and start a new link. Select the integration, then fill in the end user's details.

    Set `origin_id` to your own internal identifier for this customer. Webhook payloads carry it back, which is how you resolve an incoming event to a customer record without maintaining a separate mapping table.

    **Result:** A link on the `link.bindbee.dev` domain.
  </Step>

  <Step title="Send it to the customer">
    Forward the URL to the person who administers their HRIS - not necessarily your day-to-day contact. They'll need credentials or admin rights in the source system.

    Send the matching setup guide from [help.bindbee.dev](https://help.bindbee.dev) alongside it. Those guides are white-labelled and carry no Bindbee branding, so they're safe to forward.

    **Result:** The customer has the link and instructions for their platform.
  </Step>

  <Step title="Confirm the connection completed">
    The customer sees a confirmation screen once authorisation succeeds. The connector then appears under **Connectors** - see [Platform](/platform/overview) for what that screen shows.

    **Result:** An active connector, with a `connector_token` in its **Connector Details** panel - that's what you pass as `X-Connector-Token`. See [Authentication](/api-reference/basics/authentication).
  </Step>
</Steps>

## Hosted does not mean manual

Creating links by hand suits human-led implementation, but the same hosted page can be reached from a link created programmatically - self-serve onboarding with no front-end at all. See [Create programmatically](/how-to/connections/create-a-connector-programmatically).

The alternative surface keeps the customer inside your product instead - see [Embedded Link](/how-to/connections/embed-the-connection-flow).

## What the end user actually does

The person opening the link is your customer's HR or IT administrator, not a developer. They see their own system, are asked to authorise access, and are done.

What varies underneath is considerable. Some systems use OAuth and it takes seconds. Others need the administrator to generate an API key inside their HRIS first, create a dedicated integration user with specific role permissions, or configure a file delivery.

For those, **the flow guides them but cannot complete the work for them** - some of it happens in their HR system, not in Bindbee.

That is why per-system setup guides are written for an administrator rather than a developer, and why the harder integrations have a long tail between "link sent" and "connector active". Budget time between sending a link and data arriving.

## If this didn't work

<AccordionGroup>
  <Accordion title="The connector shows as incomplete">
    The customer opened the link but didn't finish authorising. Incomplete connectors persist and appear alongside active ones, which skews connector counts - filter to **Active Connectors** when reviewing.

    Follow up with the customer, or delete the incomplete connector and issue a fresh link.
  </Accordion>

  <Accordion title="The customer says the screen looks different from your instructions">
    The connection screen changes as integrations are updated. Point them at the current [help centre](https://help.bindbee.dev) guide rather than a screenshot captured earlier - screenshots embedded in your own onboarding material go stale silently.
  </Accordion>

  <Accordion title="The customer's credentials were wrong, or have since changed">
    Don't issue a new link. Relink the existing connector, which preserves its ID and history - see [Update credentials](/how-to/connections/update-credentials).
  </Accordion>

  <Accordion title="You need to generate links in bulk or from your own product">
    Two options. Create connectors programmatically - see [Create programmatically](/how-to/connections/create-a-connector-programmatically). Or embed the connection flow directly in your product, white-labelled with your own branding - see [Embedded Link](/how-to/connections/embed-the-connection-flow).

    Manually generated links are a reasonable way to launch; teams commonly start there and move to the embedded flow once volume justifies it.
  </Accordion>

  <Accordion title="The integration needs credentials the customer has to generate first">
    Some platforms require an API key, certificate, or private key created in their system before the link can be completed. The customer generates those first, then opens the link. The per-system guide in the help centre lists what's needed.
  </Accordion>
</AccordionGroup>
