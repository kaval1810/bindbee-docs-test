Write support expands model by model and integration by integration. An operation available on one platform may be unavailable on another, so check before building rather than discovering it from a failed request in production.

<Warning>
  There is currently no published capability matrix, and [Get Integrations](/api-reference/integrations/get-integrations) does not return per-operation write flags. The Meta API probe below is the reliable programmatic check available today.

  {/* VERIFY: a read/write capability matrix was requested in Aug 2026. If published, link it here and make it the primary method. */}
</Warning>

<Info>
  **Before you start**

  - You have a connector on the integration you're checking, or its `integration_slug`.
</Info>

## Steps

<Steps>
  <Step title="Probe the Meta endpoint">
    Each write operation has a Meta endpoint returning the request schema for that connector's integration. A schema coming back means the operation is implemented for that integration.

    | Operation | Meta endpoint |
    | --- | --- |
    | Create Employee | `GET /api/hris/v1/employees/meta/post` |
    | Create Employee Payroll Run | `GET /api/hris/v1/employee-payroll-runs/meta/post` |
    | Create Time Off | `GET /api/hris/v1/time-off/meta/post` |
    | Create Timesheet | `GET /api/hris/v1/timesheet-entry/meta/post` |

    ```bash
    curl --request GET \
      --url 'https://api.bindbee.dev/api/hris/v1/time-off/meta/post' \
      --header 'Authorization: Bearer <BINDBEE_API_KEY>' \
      --header 'X-Connector-Token: <CONNECTOR_TOKEN>'
    ```

    **Result:** A JSON Schema for the request body, or an error indicating it isn't available.
  </Step>

  <Step title="Read the schema as a capability statement">
    The schema tells you more than yes-or-no. `required` and `isRequired` show what the integration insists on, and a required `integration_params` block means the write needs platform-specific values you must source before you can call it at all.

    See [Fetch a Write Schema from the Meta API](/how-to/writing-data-back/fetch-a-write-schema).

    **Result:** You know whether the operation is available *and* whether you can satisfy its inputs.
  </Step>

  <Step title="Treat a missing schema as inconclusive, not as a no">
    A write operation can be available for an integration even when its Meta schema hasn't been implemented yet. A missing schema means you can't self-serve the contract - not necessarily that the write will fail.

    Confirm with support before concluding the operation is unsupported.

    **Result:** You avoid ruling out a capability that exists.
  </Step>

  <Step title="Check the fallback before redesigning">
    Where a unified write isn't available but the source system's own API supports the operation, [Passthrough](/how-to/writing-data-back/make-a-passthrough-request) reaches it directly - at the cost of a provider-specific request and response shape you maintain yourself.

    **Result:** You know whether the requirement is blocked or just unpretty.
  </Step>
</Steps>

## Doing this across many integrations

If you're assessing coverage across a portfolio rather than one connector, iterate [Get Integrations](/api-reference/integrations/get-integrations) for the list, then probe the relevant Meta endpoint per connector. Cache the result per integration - capability changes at release cadence, not per request.

## If this didn't work

<AccordionGroup>
  <Accordion title="The Meta endpoint returns 403">
    The credentials are valid but the operation isn't permitted for this connector - either the write is disabled for that model, or the connector belongs to a different API category. See [Authenticate a Request](/how-to/setup/authenticate-a-request).
  </Accordion>

  <Accordion title="The schema returns but the write fails validation">
    The schema is the contract Bindbee expects; the source system can impose rules beyond it - a code that must exist in their configuration, a date within an open period, an approval state. Those surface at write time.

    See [Fetch a Write Schema from the Meta API](/how-to/writing-data-back/fetch-a-write-schema).
  </Accordion>

  <Accordion title="You need writes for a model with no Meta endpoint">
    Meta endpoints cover the four operations above. Other writes, where available, have no schema probe. Passthrough is the general fallback.
  </Accordion>

  <Accordion title="A customer is asking what's writable before they sign">
    Probe against a sandbox connector on that integration if you have one. Where you don't, ask support rather than inferring from another platform - write support is not consistent across integrations, and reads being available says nothing about writes.
  </Accordion>
</AccordionGroup>
