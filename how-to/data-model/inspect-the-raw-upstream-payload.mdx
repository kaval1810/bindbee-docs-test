---

When a value exists in the HRIS but not in the unified response, it is almost always present in the raw upstream payload. Inspect that payload to find the exact path, then map it.

<Info>
  **Before you start**

  - You know the model the field should belong to - `employee`, `employment`, `benefit`, and so on.
  - The connector has completed at least one sync, or you accept the integration's canned sample instead.
</Info>

## Steps

<Steps>
  <Step title="Fetch the raw payload">
    Call the raw-data endpoint with the category and model slug. Pass `connector_token` to see this connector's most recent synced row, or `integration_slug` to see a generic sample for the integration.

    ```bash
    curl --request GET \
      --url 'https://api.bindbee.dev/api/v1/custom-fields/raw-data?category=HRIS&model=employee&connector_token=<CONNECTOR_TOKEN>' \
      --header 'Authorization: Bearer <BINDBEE_API_KEY>'
    ```

    **Result:** The untransformed JSON the source system returned for one record.

    <Tip>
      If the connector has never synced, the endpoint falls back to the integration's canned sample. That's enough to write a mapping against, but confirm the shape once real data lands.
    </Tip>
  </Step>

  <Step title="Locate the field">
    Search the payload for the value you expect. Match on the value, not the field name - source systems rarely name things the way their UI does.

    **Result:** You have a JSON path, for example `personalInfo.birthDate` or `customFieldGroup[0].value`.
  </Step>

  <Step title="Write a JMESPath expression">
    Convert the location into a [JMESPath](https://jmespath.org/) expression.

    | What you see | Expression |
    | --- | --- |
    | `{"personalInfo": {"birthDate": "1991-03-16"}}` | `personalInfo.birthDate` |
    | `{"fields": [{"name": "Cost Center", "value": "ENG-NA"}]}` | `fields[?name=='Cost Center'].value \| [0]` |
    | `{"customField4611": "REG"}` | `customField4611` |

    **Result:** An expression that resolves to a single value.
  </Step>

  <Step title="Confirm it resolves">
    Dry-run the expression before saving it, using the dashboard's preview control or the preview endpoint. See [Test a JMESPath Before Saving It](/how-to/data-model/test-a-jmespath).

    **Result:** The preview returns your value rather than `null`.
  </Step>
</Steps>

## What you just did

You found the source path. To surface the field in API responses, map it - from the [dashboard](/how-to/data-model/map-a-custom-field-from-the-dashboard) for one-off changes, or via the [API](/how-to/data-model/map-custom-fields-with-the-api) when the configuration needs to be versioned or replicated across environments.

## If this didn't work

<AccordionGroup>
  <Accordion title="The field isn't in the payload at all">
    Two likely causes.

    The field may not be in scope for this connector. Some models and fields are excluded from sync by configuration - see [Restrict Which Models and Fields Sync](/how-to/data-model/restrict-models-and-fields).

    Or the source system may not expose it on this endpoint. Several HRIS platforms return different field sets to different API surfaces, and permission level changes what's returned - see [Resolve a Source-System Permission Error](/how-to/troubleshooting/resolve-a-permission-error). If the field is genuinely absent from the API, the source system's own configuration usually has to change first.
  </Accordion>

  <Accordion title="The payload looks different from another connector on the same integration">
    Expected. Payload shape varies with the source system's configuration, plan tier, and enabled modules, so two connectors on the same integration can differ.

    Map at connector level for these, and reserve integration-level mappings for fields that are genuinely consistent. See [Scope a Mapping to One Connector or All](/how-to/data-model/scope-a-mapping).
  </Accordion>

  <Accordion title="The value appears in raw data but the mapped field returns INVALID_JSON_PATH">
    The expression didn't resolve. Bindbee returns `"INVALID_JSON_PATH"` in place of the value rather than raising an error, so this surfaces at read time rather than at save time.

    Most often it's an array that needs an index or a filter, or a quoting error inside a filter expression.
  </Accordion>

  <Accordion title="You need the raw payload in the API response instead">
    Add `include_raw_data=true` to a unified endpoint to get `raw_data` inline per record. That's useful for spot checks across many records; the raw-data endpoint above is better for discovering structure on one.
  </Accordion>
</AccordionGroup>
