---
title: "Validate Webhook Signatures"
description: "Verify that an incoming webhook genuinely came from Bindbee and wasn't tampered with in transit."
---

Your webhook endpoint is publicly reachable, so anyone can `POST` to it. Every request carries an `X-Bindbee-Webhook-Signature` header - an HMAC-SHA256 of the raw request body, keyed with your organization's signature key. Verify it before acting on the payload.

<Info>
  **Before you start**

  - You have a webhook receiving deliveries - see [Create a Webhook](/how-to/reliability/create-a-webhook).
  - Your framework can expose the **raw** request body.
</Info>

## Steps

<Steps>
  <Step title="Get the signature key">
    Open **Webhooks** in the dashboard and copy the key from the **Security** section. It's unique to your organization and can be regenerated if it's ever exposed.

    Store it as a secret alongside your API keys.

    **Result:** You have the key.
  </Step>

  <Step title="Capture the raw body">
    Compute the HMAC over the exact bytes received. Re-serialising parsed JSON changes whitespace and key order, and the signature will never match.

    In Express, capture it in the `verify` hook before the JSON parser consumes it.

    **Result:** You have the unmodified body.
  </Step>

  <Step title="Compute and compare">
    HMAC-SHA256 over the raw body with your key, base64url-encoded, compared in constant time.

    <CodeGroup>
      ```python Python
      import base64, hashlib, hmac

      signature_key = "YOUR_WEBHOOK_SIGNATURE_KEY"

      if "X-Bindbee-Webhook-Signature" not in request.headers:
          raise ValueError("Signature header missing; request may not be from Bindbee.")

      received_signature = request.headers["X-Bindbee-Webhook-Signature"]

      hmac_digest = hmac.new(
          signature_key.encode("utf-8"),
          request.body.encode("utf-8"),
          hashlib.sha256,
      ).digest()

      encoded_digest = base64.urlsafe_b64encode(hmac_digest).decode()
      signature_valid = hmac.compare_digest(encoded_digest, received_signature)
      ```

      ```javascript Node
      const crypto = require("crypto");

      app.use(express.json({
        verify: (req, res, buf) => { req.rawBody = buf.toString(); },
      }));

      // Node lower-cases incoming header names - the mixed-case key is always undefined
      const receivedSignature = req.headers["x-bindbee-webhook-signature"];
      if (!receivedSignature) throw new Error("Signature header missing.");

      const hmacDigest = crypto
        .createHmac("sha256", WEBHOOK_SECRET)
        .update(req.rawBody)
        .digest("base64")
        .replace(/\+/g, "-")
        .replace(/\//g, "_");

      const a = Buffer.from(receivedSignature, "utf-8");
      const b = Buffer.from(hmacDigest, "utf-8");
      const isSignatureValid =
        a.length === b.length && crypto.timingSafeEqual(a, b);
      ```

      ```ruby Ruby
      require 'base64'
      require 'openssl'

      # Rack exposes headers as HTTP_-prefixed env keys; request.headers does the mapping
      received_signature = request.headers['X-Bindbee-Webhook-Signature']
      raise "Signature header missing." unless received_signature

      request_body = request.raw_post.force_encoding('UTF-8')

      hmac_digest = OpenSSL::HMAC.digest(
        OpenSSL::Digest.new('sha256'), WEBHOOK_SECRET, request_body
      )
      encoded_digest = Base64.urlsafe_encode64(hmac_digest)

      valid_signature = ActiveSupport::SecurityUtils.secure_compare(
        encoded_digest, received_signature
      )
      ```
    </CodeGroup>

    Note the encoding is **base64url** - `-` and `_` rather than `+` and `/`. Standard base64 fails to match on roughly one payload in forty, which reads as an intermittent bug rather than an encoding error.

    Compare with a constant-time function, never `==`.

    **Result:** A boolean you can branch on.
  </Step>

  <Step title="Reject invalid requests, but acknowledge fast">
    Return a non-`2xx` for a failed signature so the request isn't silently accepted.

    Keep verification cheap and respond within the 10-second timeout - verification runs before your business logic, so slow verification affects every delivery.

    **Result:** Only authentic payloads reach your processing.
  </Step>
</Steps>

## If this didn't work

<AccordionGroup>
  <Accordion title="Signatures never match">
    In order of likelihood: the body was parsed and re-serialised rather than used raw; standard base64 was used instead of base64url; the key was copied with trailing whitespace; or the key came from a different organization.

    Log the received signature alongside your computed one for a single request to see which.
  </Accordion>

  <Accordion title="Signatures match sometimes">
    Base64url. Payloads whose digest contains no `+` or `/` bytes match under standard base64 and the rest don't, producing exactly this pattern.
  </Accordion>

  <Accordion title="The header is missing">
    The request may not be from Bindbee. Also check no proxy or load balancer is stripping unrecognised headers - some strip `X-` headers by default.
  </Accordion>

  <Accordion title="You regenerated the key and deliveries started failing">
    Regeneration takes effect immediately for the whole organization. Deploy the new key before regenerating, or accept a gap where deliveries fail verification - and note that a failed verification consumes retry attempts, after which the delivery is not redelivered.
  </Accordion>
</AccordionGroup>
