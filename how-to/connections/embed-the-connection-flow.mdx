title: "Embedded Link"

A [Magic Link](/explanation/magic-link) takes your customer to a Bindbee-hosted page. Embedding the same flow keeps them inside your product, under your own logo and colours, and hands your backend the `connector_token` directly.

<Info>
  **Before you start**

  - An API key for the environment you are connecting in - see [Environments](/how-to/setup/choose-an-environment)
  - The category and integration slug you are connecting - see [Integration slugs & variants](/how-to/setup/look-up-an-integration-slug)
  - A frontend you can add a script or an npm package to
</Info>

## Steps

<Steps>
  <Step title="Generate a link token">
    A `link_token` initialises one embed session for one end customer. Create it from your backend, never the browser - it is issued against your API key.

    <CodeGroup>

    ```bash cURL
    curl --request POST \
      --url 'https://api.bindbee.dev/api/embedded/v1/link/create-link-token' \
      --header 'Authorization: Bearer <BINDBEE_API_KEY>' \
      --header 'Content-Type: application/json' \
      --data '{
        "end_user_data": {
          "org_name": "Acme Corp.",
          "origin_id": "064e1cd7-49ad-4e6d-8005-7e4c92fe9675"
        },
        "category": "HRIS",
        "integration": "bamboohr"
      }'
    ```

    ```python Python
    import os, requests

    resp = requests.post(
        "https://api.bindbee.dev/api/embedded/v1/link/create-link-token",
        headers={"Authorization": f"Bearer {os.environ['BINDBEE_API_KEY']}"},
        json={
            "end_user_data": {
                "org_name": "Acme Corp.",
                "origin_id": "064e1cd7-49ad-4e6d-8005-7e4c92fe9675",
            },
            "category": "HRIS",
            "integration": "bamboohr",
        },
        timeout=30,
    )
    resp.raise_for_status()
    link_token = resp.json()["link_token"]
    ```

    </CodeGroup>

    Set `origin_id` to your own identifier for that customer. It is what resolves a connector back to your records later, and it cannot be added afterwards.

    **Result:** a `link_token` to hand to your frontend.
  </Step>

  <Step title="Mount the flow in your frontend">
    Use the React package if you have React, the CDN script otherwise. `@bindbee/react-link` is the only SDK Bindbee ships - everything else is a plain HTTP call.

    ```bash
    npm install --save @bindbee/react-link
    # or
    yarn add @bindbee/react-link
    ```

    <CodeGroup>

    ```jsx React
    import { useBindbeeMagiclink } from "@bindbee/react-link";

    const Connect = ({ linkToken }) => {
      const { open } = useBindbeeMagiclink({
        linkToken,
        // serverUrl: "https://api-eu.bindbee.dev",  // EU region only
        onSuccess: (temporaryToken) => sendToBackend(temporaryToken),
        onClose: () => console.log("closed without finishing"),
      });
      return <button onClick={open}>Connect your HR system</button>;
    };
    ```

    ```html CDN
    <script
      src="https://cdn.bindbee.dev/initialize.min.js"
      integrity="sha512-1L1XqHiVgenLFd95eE8fqJ7o6kje+5+3IN7K0cuwNP6feTrYAeNTdpeqR1e2HgThSb5Bj+USqJeNiyEE9KBtfA=="
      crossorigin="anonymous"
    ></script>

    <script>
      window.BindbeeEmbed.initialize({
        linkToken: "LINK_TOKEN",
        onSuccess: (temporaryToken) => sendToBackend(temporaryToken),
        onClose: () => {},
      });
      // window.BindbeeEmbed.open() to launch, .destroy() to clean up
    </script>
    ```

    </CodeGroup>

    **Result:** your customer completes authorization without leaving your product, and `onSuccess` returns a `temporary_token`.
  </Step>

  <Step title="Exchange the temporary token for a connector token">
    The `temporary_token` is short-lived and cannot read data. Exchange it from your backend and store the result.

    ```bash cURL
    curl --request GET \
      --url 'https://api.bindbee.dev/api/embedded/v1/connectors/connector_token/<TEMPORARY_TOKEN>' \
      --header 'Authorization: Bearer <BINDBEE_API_KEY>'
    ```

    The response carries both identifiers:

    ```json
    { "connector_token": "...", "connector_id": "..." }
    ```

    Store both. `connector_token` authenticates every later call; `connector_id` is what you use for support, feature-flagging, and keying stored tokens - see [Go-live checklist](/how-to/setup/go-live-checklist).

    **Result:** a `connector_token`, stored against your customer record. Every later read or write for that customer carries it.
  </Step>

  <Step title="Apply your branding">
    Go to **Settings → Organization** in the Dashboard and set your **logo**, **favicon** and **brand colour**. The embedded component picks them up, so the flow matches your product rather than Bindbee's.

    Logo and favicon are limited to 1 MB each.

    **Result:** the embedded flow renders in your own branding for every customer.
  </Step>
</Steps>

## React reference

`@bindbee/react-link` is the only SDK Bindbee publishes.

```jsx
import { useBindbeeMagiclink } from "@bindbee/react-link";

const { open } = useBindbeeMagiclink({
  linkToken,
  onSuccess: (temporaryToken) => sendToBackend(temporaryToken),
  onClose: () => {},
});
```

| Option | Type | Required | Purpose |
| --- | --- | --- | --- |
| `linkToken` | `string` | Yes | The `link_token` for this end customer. One token initialises one session |
| `onSuccess` | `(temporaryToken: string) => void` | Yes | Fires in the browser when authorisation completes. Send the value to your backend |
| `onClose` | `() => void` | No | Fires when the customer dismisses the flow without finishing |
| `serverUrl` | `string` | No | Region override. Defaults to `https://api.bindbee.dev`; set `https://api-eu.bindbee.dev` for EU |

The hook returns `open` - call it to launch the flow, typically from a button handler.

## CDN reference

For any framework other than React, load the script and use the `BindbeeEmbed` global. An unminified build is served at `initialize.js` with its own `integrity` hash.

| Method | Purpose |
| --- | --- |
| `BindbeeEmbed.initialize(options)` | Configure the flow. Takes `linkToken`, `onSuccess` and `onClose`, as above |
| `BindbeeEmbed.open()` | Launch the flow |
| `BindbeeEmbed.destroy()` | Tear it down and release its listeners |

<Warning>
  The `integrity` hash must match the build you reference, or the browser
  refuses to execute the script and the flow never renders. If your CSP blocks
  the load, allow `cdn.bindbee.dev`.
</Warning>

## Notes

- The API key never reaches the browser. Only the `link_token` does, and it initialises one session for one end customer.
- `category` and `integration` are fixed when the `link_token` is created. The end user does not choose a system.
- A `temporary_token` is not a `connector_token` and cannot read data.
- Branding comes from **Settings → Organization**, not from these options.

## If this didn't work

<AccordionGroup>
  <Accordion title="The connector was created in the wrong environment">
    The environment follows the API key that created the `link_token`, not anything in the frontend. A Development key produces a Development connector, which will not sync on a schedule. See [Environments](/how-to/setup/choose-an-environment).
  </Accordion>

  <Accordion title="The flow opens but the integration list is wrong or empty">
    `category` and `integration` are fixed when the token is created, not chosen by the user. Check the slug - see [Integration slugs & variants](/how-to/setup/look-up-an-integration-slug).
  </Accordion>

  <Accordion title="onSuccess fired but API calls still return 403">
    A `temporary_token` is not a `connector_token`. Requests for customer data need the exchanged token in `X-Connector-Token`.
  </Accordion>

  <Accordion title="The CDN script is blocked or fails to load">
    The `integrity` hash must match the file you reference. If your CSP blocks it, allow `cdn.bindbee.dev`; the unminified build at `initialize.js` has its own hash.
  </Accordion>

  <Accordion title="You need a link without building a frontend">
    Send a hosted link instead - see [Magic Link](/explanation/magic-link) - or create connectors from your backend with [Create programmatically](/how-to/connections/create-a-connector-programmatically).
  </Accordion>
</AccordionGroup>
