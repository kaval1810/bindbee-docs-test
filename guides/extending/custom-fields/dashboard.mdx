Creating a Custom Field from the dashboard is two steps: create the field, then map it to a value in the source system's raw payload. For the concepts see the [Custom Fields overview](/guides/extending/custom-fields). For the programmatic route see [API Configuration](/guides/extending/custom-fields/api-workflow).

## The Custom Fields page

**Configure → Custom Fields** lists every field in your organisation, with how many mappings each has, its category and model, and who last changed it.

<Frame caption="Configure → Custom Fields. The Mapping column counts how many mappings a field has — a field with none carries no data yet.">
  <img src="/images/custom-fields/custom-fields-list.png" alt="The Custom Fields page listing fields with their mapping count, category, selected model, last updated date and creator" />
</Frame>

## Step 1: Create the field

Click **New Field** in the top right.

<Frame caption="The Create custom field dialog. Category and model are chosen together — the field belongs to that pair.">
  <img src="/images/custom-fields/create-field-dialog.png" alt="Create custom field dialog with fields for name, category, model and short description" />
</Frame>

| Field | Notes |
| --- | --- |
| **Name of custom field** | Required. Must be unique and follow `snake_case`, for example `employee_insurance_id`. |
| **Select model** | Required. Pick the **Category** first, then the **model** the field extends. |
| **Short Description** | Optional. A note explaining what the field holds. |

Press **Create**. The field now exists but carries no data — it needs a mapping.

## Step 2: Choose the mapping type

You land on the field's page, which prompts you to create the first mapping. The two options are the two scopes.

<Frame caption="Create your first mapping. The panel below summarises the same three steps this page walks through.">
  <img src="/images/custom-fields/first-mapping.png" alt="Custom field info page offering for Specific Connector or for Integration as the first mapping, above a Steps to create custom field panel" />
</Frame>

| Option | Applies to |
| --- | --- |
| **for Specific Connector** | Selected connectors only |
| **for Integration** | Every connector using that integration |

<Info>
  Where both exist for the same field, the connector mapping wins on that connector. See [Scopes](/guides/extending/custom-fields#scopes).
</Info>

## Step 3: Pick the source

A mapping row has three parts: **Mapping type**, **Source**, and **Data field**.

For a connector mapping, the Source dropdown is a searchable list of your connectors:

<Frame caption="Connector mappings pick one connector by name. The list is searchable.">
  <img src="/images/custom-fields/mapping-for-connector.png" alt="Mapping row set to for Connector with the Select Connector dropdown open, showing a searchable list of connectors" />
</Frame>

For an integration mapping, it is the integration itself:

<Frame caption="Integration mappings apply to every connector on that integration.">
  <img src="/images/custom-fields/mapping-for-integration.png" alt="Mapping row set to for Integration with BambooHR selected as the source" />
</Frame>

Use **Add new** to give one field several mappings — different connectors, or a connector override alongside an integration default.

## Step 4: Select the data field

Click the **Data field** box to open the picker. It has two tabs.

### Live data

Search a real employee, then choose a value from their raw payload. Because you can see the actual value, this is the surest way to confirm you are mapping the right key.

<Frame caption="Live data. Pick an employee on the left, then a field from their raw data on the right.">
  <img src="/images/custom-fields/data-field-live-data.png" alt="Data field picker on the Live data tab, with an employee search list beside the raw data fields for the selected employee" />
</Frame>

<Warning>
  **Live data is only available for the Employee model on connector-level custom fields.** For any other model, or for an integration-level mapping, use the JSON Path tab.
</Warning>

### JSON Path

Browse a sample payload and select the field you want, or switch to **Enter path** and type the expression directly.

What the sample shows depends on the scope of the mapping. A connector mapping shows that connector's own data:

<Frame caption="A connector mapping previews sample data from that specific connector.">
  <img src="/images/custom-fields/data-field-json-path-connector.png" alt="JSON Path tab showing sample data from a named connector, with search and enter path controls" />
</Frame>

An integration mapping has no single connector to read from, so it shows a sample from one of your connectors on that integration:

<Frame caption="An integration mapping previews a sample from one of your connectors on that integration, not from a specific one.">
  <img src="/images/custom-fields/data-field-json-path-integration.png" alt="JSON Path tab showing sample data from one of your BambooHR connectors, with a tooltip explaining the live data limitation" />
</Frame>

Select the field, then press **Map field**. Save the mapping row with the tick.

<Note>
  Structures differ between integrations. An expression that works on one platform will not necessarily work on another, so check each integration you map rather than assuming the shape carries over.
</Note>

## When the value appears

**The field is populated on the connector's next sync**, not immediately. To see it sooner, [force a resync](/guides/reading-writing/syncing#forcing-a-resync).

Once it resolves, request it with `include_custom_fields=true` — see [Retrieve custom fields](/guides/extending/custom-fields#retrieve-custom-fields).

<Warning>
  An incorrect path does not raise an error. The API returns `"INVALID_JSON_PATH"` in place of the value, so confirm the mapping resolves before relying on it.
</Warning>
