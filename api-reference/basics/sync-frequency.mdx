A Production connector pulls scoped data on a schedule. **The cadence is a property of the connector**, so different customers can run on different schedules.

## Available cadences

| Cadence | Fits |
| --- | --- |
| 6 hours | Same-day propagation - eligibility, enrolment, onboarding |
| 24 hours *(default)* | Most workflows |
| Weekly | Reference data that changes rarely, or slow source systems |

**Six hours is the floor.** It is not an arbitrary limit: each sync pulls the full in-scope dataset from the source system, and most HR systems permit only a small number of requests per minute per tenant. Some cannot sustain a full extract every six hours, and a shorter cadence produces failures rather than fresher data.

<Note>
  Development connectors have no schedule at all. Every sync is one you trigger - see [Syncing](/explanation/how-syncing-works).
</Note>

## Start time

Cadence sets how often; start time sets when in the day. Both are per connector, and both are changed the same way.

<Warning>
  Neither is a dashboard control today. Send support the connector IDs, the cadence, and - if you are setting one - the start time with its timezone.

## What the schedule does not bound

The cadence is a ceiling on freshness, not a guarantee of it. A sync that starts on time can still finish after your processing window, and duration grows with population size.

**Gating your job on the sync-completed event removes that race entirely**, and works regardless of when the sync starts or how long it takes. Aligning to a fixed clock only narrows it.
