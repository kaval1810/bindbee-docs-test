## Magic Link

A connection page Bindbee hosts for you. Send it to whoever runs your customer's HR system; they sign in and approve access, and the connector is created. **Their credentials never pass through your product**, and you don't build any of these screens.

See [How to connect](/get-started/how-to-connect) for this and the two other routes.

## Connectors

A connector is one customer's authorised link to one third-party system - **one connector = per customer, per system.** Find them under **Connectors**, with separate **Development** and **Production** tabs.

### Moving, renaming and deleting

| Action | What happens | How |
| --- | --- | --- |
| **Move between environments** | Keeps the authorisation and every ID you have stored - nobody reconnects. Switch those calls to the target environment's API key. | Ask support |
| **Rename** | Changes the display name only. Match connectors on `origin_id`, never on the name. | Ask support |
| **Delete** | Discards the synced data *and the record IDs built from it*. Fine for an abandoned, duplicate or churned connector; [relink](/guides/troubleshooting/connections-to-relink) expired credentials and [resync](/guides/reading-writing/syncing) bad data instead. | [Delete Connector](/api-reference/connectors/delete-connector) |

## Logs

Every request and response, per connector, with the source system's own error preserved. Open **Logs**, or reach one connector's logs from its own page.

When a sync misbehaves this is the first place to look - see [Logs](/guides/troubleshooting/logs).
