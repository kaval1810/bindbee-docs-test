## Prerequisites

- A Bindbee account. Access is provisioned during onboarding. If you don't have access, email [Bindbee Support](mailto:support@bindbee.dev).
- Your **Development API key** from [Bindbee Dashboard](https://app.bindbee.dev/settings/keys).

<Steps>

<Step title="Create a test connector">

1. Go to [app.bindbee.dev](https://app.bindbee.dev) and open **Connectors**.

2. Switch to the **Development** tab and press **+ Test Connector**.
<Frame caption="Connectors → Development. The notice here is about recurring syncs — the first one still runs on its own.">
  <img src="/images/quickstart/connectors-development.png" alt="The Connectors page on the Development tab, noting that development connectors do not sync automatically, with a Test Connector button" />
</Frame>

3. Select a category and an integration for example **BambooHR** under HRIS.
<Frame caption="Create Connector → Select integration. The Unique Customer ID is the `origin_id` you'll use to match this connector back to your own customer record.">
  <img src="/images/quickstart/select-integration.jpg" alt="The Create Connector form with an Organisation Name field, a Categories dropdown set to HRIS and a Unique Customer ID field, beside the Select integration panel with API and SFTP tabs and BambooHR selected from the integration grid" />
</Frame>

4. Follow the prompts to complete authorisation.
<Frame caption="The authorisation screens your customer sees. Access is granted per data model, and which methods are offered depends on the integration.">
  <img src="/images/quickstart/test-connector-authentication.jpg" alt="A consent screen reading 'Bindbee is requesting access to BambooHR', listing data models including Benefit, Company, Compensation, Employee, Employment and Time Off with read access ticked and an Allow and Continue button, beside a 'How do you want to Authenticate?' panel offering OAuth Authentication marked Recommended or using your own API key" />
</Frame>

5. Once the connector is created, **open it and copy the **`connector_token`**** from the **Overview** tab.

Provisioning one can take a while, so start it before the rest of this page if your integration needs it.

</Step>

<Step title="Wait for the first sync">

The connector starts its initial sync the moment authorisation completes — a full read of every model in scope. It usually finishes in a couple of minutes.

<Warning>
  **Reads before it finishes return `200` with partial or empty results.** There is no error and nothing on the response to distinguish them.
</Warning>

Open the connector and watch the **Sync** panel. Wait until the run's **Status** reads **Synced**.

<Frame caption="The connector's Sync panel. Wait for Status to read Synced before calling the API; Force Sync triggers the next run.">
  <img src="/images/quickstart/sync-panel.jpg" alt="The Sync panel on a connector, listing sync #1 with trigger Automatic, status Synced, and the time it completed, alongside a Force Sync button" />
</Frame>

A run can finish and still leave the connector holding nothing — if the source system had no records in scope, or the credentials could not reach them.

<Note>
  **In Development, only the first sync runs on its own.** After that, press **Force Sync** or call [Force sync a connector](/api-reference/connectors/resync-connector) whenever you want fresh data. Production connectors sync [on a schedule](/api-reference/basics/sync-frequency).
</Note>

</Step>

<Step title="Make your first API call">

Send a `GET` request to the Employees endpoint:

```bash
curl https://api.bindbee.dev/api/hris/v1/employees \
  -H "Authorization: Bearer YOUR_DEV_API_KEY" \
  -H "X-Connector-Token: YOUR_CONNECTOR_TOKEN"
```

Every field the response can carry, with a sample payload, is on [Get Employees](/hris/employee/get-employees).

</Step>

</Steps>

## What just happened

1. You created a **connector** — one authorized connection to one source system.
2. You **synced** it, pulling that system's data into Bindbee.
3. You called the **Unified API** with your API key and the connector token, and got normalised data.

That is the core of every Bindbee integration. In production two things change: connectors sync on a schedule rather than on manual trigger, and your end users create them through Magic Link or Embedded SDK rather than you entering credentials. Checkout [How to connect](/get-started/how-to-connect).
