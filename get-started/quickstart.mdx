## Prerequisites

- A Bindbee account. Access is provisioned during onboarding — there is no self-serve signup. If you don't have access, email [support@bindbee.dev](mailto:support@bindbee.dev).
- Your **Development API key** from [app.bindbee.dev/settings/keys](https://app.bindbee.dev/settings/keys).

<Steps>

<Step title="Create a test connector">

1. Go to [app.bindbee.dev](https://app.bindbee.dev) and open **Connectors**.
2. Switch to the **Development** tab and press **+ Test Connector**.
3. Select a category and an integration — for example **BambooHR** under HRIS.
4. Follow the prompts to complete authorisation.

<Frame caption="Connectors → Development. The notice here is about recurring syncs — the first one still runs on its own.">
  <img src="/images/quickstart/connectors-development.png" alt="The Connectors page on the Development tab, noting that development connectors do not sync automatically, with a Test Connector button" />
</Frame>

Once the connector is created, open it and copy the **`connector_token`** from the **Overview** tab. You need it in step 3.

</Step>

<Step title="Wait for the first sync">

The connector starts its initial sync the moment authorisation completes — a full read of every model in scope. On a small test tenant it usually finishes in a couple of minutes.

<Warning>
  **Reads before it finishes return `200` with partial or empty results.** There is no error and nothing on the response to distinguish them — an employee list still filling looks exactly like a customer with no employees.
</Warning>

Wait for the run's **Status** to read **Synced** in the connector's **Sync** panel. The API calls that same value `sync_status`, where it reads `Done`.

Two fields on the connector answer different questions over the API, and both matter beyond this page:

| Field | Answers | Watch for |
| --- | --- | --- |
| `status` | Are the credentials good? | `RELINK_NEEDED` |
| `sync_status` | Did the last run succeed? | `Failed` |

A connector can be `COMPLETE` and still hold no data.

<Note>
  **That first sync is the only automatic one in Development.** There is no recurring schedule here, so every refresh after it is one you trigger — press **Force Sync**, or call [Force sync a connector](/api-reference/connectors/resync-connector). Production connectors run on a schedule instead; see [Sync frequency](/api-reference/basics/sync-frequency).
</Note>

</Step>

<Step title="Make your first API call">

Send a `GET` request to the Employees endpoint:

```bash
curl https://api.bindbee.dev/api/hris/v1/employees \
  -H "Authorization: Bearer YOUR_DEV_API_KEY" \
  -H "X-Connector-Token: YOUR_CONNECTOR_TOKEN"
```

</Step>

</Steps>

## What just happened

1. You created a **connector** — one authorized connection to one source system.
2. You **synced** it, pulling that system's data into Bindbee's copy.
3. You called the **Unified API** with your API key and the connector token, and got normalised data back.

That is the core of every Bindbee integration. In production two things change: connectors sync on a schedule rather than on demand, and your end users create them through Magic Link rather than you entering credentials — see [How to connect](/get-started/how-to-connect).
