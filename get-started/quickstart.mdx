By the end of this page you will have created a test connection, triggered a sync, and read normalized employee data out of the Bindbee API.

<Info>
  **Time to first API call: ~10 minutes.** Everything here runs in the
  **Development** environment, which is isolated from Production and free to
  experiment in.
</Info>

## Before you start

You need a Bindbee account. If you don't have one, [book a demo](https://www.bindbee.dev/book-demo) or sign in at [app.bindbee.dev](https://app.bindbee.dev).

You will also need `curl`, or any HTTP client.

---

## Step 1 — Get your Development API key

Go to **Settings → API Keys** at [app.bindbee.dev/settings/keys](https://app.bindbee.dev/settings/keys) and copy your **Development** key.

<img
  src="https://images.unifyx.dev/documentation_images/development-key.png"
  alt="Development API Keys"
  className="block"
/>

Export it so the rest of the commands on this page work as written:

```bash
export BINDBEE_API_KEY="your_development_api_key"
export BINDBEE_URL="https://api.bindbee.dev"   # use https://api-eu.bindbee.dev for the EU region
```

<Warning>
  Make sure you copied the **Development** key. A Production key will not work
  against Development data, and using one here would create a live connector.
</Warning>

---

## Step 2 — Confirm the key works

The lookup endpoints are organization-scoped, so they need only the API key. This is the fastest way to prove your credentials are correct before anything else can go wrong.

```bash
curl "$BINDBEE_URL/api/v1/lookup/integrations" \
  -H "Authorization: Bearer $BINDBEE_API_KEY"
```

A `200` with a list of integrations means you are authenticated.

If you get `401`, the key is wrong or the `Bearer ` prefix is missing. See [Authenticate a request](/how-to/authenticate).

---

## Step 3 — Create a connection

A **connector** represents one customer's link to one system. You have two ways to create one.

<Tabs>
  <Tab title="Magic Link (fastest)">
    No code. Best for your first run.

    1. In the dashboard, go to **Magic Link** and click **Create Magic Link**.
    2. Choose category **HRIS** and pick an integration.
    3. Enter an organization name (e.g. `Acme Corp`) and an `origin_id` — use
       your own internal customer ID.
    4. Open the generated link and complete the authorization as if you were the
       customer.

    Full walkthrough: [Magic Link](/features/magic-link).
  </Tab>
  <Tab title="Bindbee Embed (in your product)">
    Generate a `link_token`, render the flow in your frontend, then exchange the
    resulting `temporary_token` for a `connector_token`.

    ```bash
    curl -X POST "$BINDBEE_URL/api/embedded/v1/link/create-link-token" \
      -H "Authorization: Bearer $BINDBEE_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "end_user_data": {
          "org_name": "Acme Corp.",
          "origin_id": "your-internal-customer-id"
        },
        "category": "HRIS",
        "integration": "bamboohr"
      }'
    ```

    Full walkthrough: [Bindbee Embed](/sdk/bindbee-embed).
  </Tab>
</Tabs>

Integration slugs (`bamboohr`, `workday`, `ukg-pro`, …) are listed on the [Integrations](/integrations) page.

## Step 4 — Get your `connector_token`

List your connectors and find the one you just created:

```bash
curl "$BINDBEE_URL/api/hris/v1/connectors" \
  -H "Authorization: Bearer $BINDBEE_API_KEY"
```

```json

  "cursor": null,
  "page_size": 50,
  "items": [
    {
      "id": "018b18ef-c487-703c-afd9-0ca478ccd9d6",
      "integration_slug": "bamboohr",
      "category": "HRIS",
      "status": "COMPLETE",
      "sync_status": "Done",
      "origin_id": "your-internal-customer-id",
      "connector_token": "jk23h4jk23hk4j2h3kj4h23kjh4k23jh4k2j3h4",
      "is_active": true
    }
  ]
}
```

You can also read the token from the **Overview** tab of the connector in the dashboard.

```bash
export CONNECTOR_TOKEN="jk23h4jk23hk4j2h3kj4h23kjh4k23jh4k2j3h4"
```

<Tip>
  In a real integration, store `connector_token` against your own customer record
  the moment you receive it. You will need it on every subsequent request for
  that customer.
</Tip>

## Step 5 — Trigger a sync

Development connectors **do not sync automatically**. Nothing will be readable until you run one:

```bash
curl -X POST "$BINDBEE_URL/api/embedded/v1/connectors/resync" \
  -H "Authorization: Bearer $BINDBEE_API_KEY" \
  -H "X-Connector-Token: $CONNECTOR_TOKEN"
```

Poll the connector until `sync_status` is `Done`:

```bash
curl "$BINDBEE_URL/api/hris/v1/connectors" \
  -H "Authorization: Bearer $BINDBEE_API_KEY"
```

The `sync_progress` field reports percentage complete while a sync is running.

<Note>
  In **Production** this step is unnecessary — syncs run automatically every 24
  hours by default, and the first sync starts as soon as the customer finishes
  linking. See [Force a resync](/how-to/force-a-resync) for when it *is*
  appropriate.
</Note>

## Step 6 — Read unified employee data

This is the call your product will actually make. Note that it needs **both** headers:

<CodeGroup>

```bash cURL
curl "$BINDBEE_URL/api/hris/v1/employees?page_size=10" \
  -H "Authorization: Bearer $BINDBEE_API_KEY" \
  -H "X-Connector-Token: $CONNECTOR_TOKEN"
```

```python Python
import os, requests

resp = requests.get(
    "https://api.bindbee.dev/api/hris/v1/employees",
    headers={
        "Authorization": f"Bearer {os.environ['BINDBEE_API_KEY']}",
        "X-Connector-Token": os.environ["CONNECTOR_TOKEN"],
    },
    params={"page_size": 10},
)
resp.raise_for_status()
for employee in resp.json()["items"]:
    print(employee["display_full_name"], employee["work_email"])
```

```javascript Node
const res = await fetch(
  "https://api.bindbee.dev/api/hris/v1/employees?page_size=10",
  {
    headers: {
      Authorization: `Bearer ${process.env.BINDBEE_API_KEY}`,
      "X-Connector-Token": process.env.CONNECTOR_TOKEN,
    },
  },
);

if (!res.ok) throw new Error(`${res.status} ${await res.text()}`);

const { items } = await res.json();
for (const employee of items) {
  console.log(employee.display_full_name, employee.work_email);
}
```

## Troubleshooting your first call

| Symptom | Cause | Fix |
| --- | --- | --- |
| `401 Unauthorized` | Missing `Bearer ` prefix, or wrong environment key | [Authenticate a request](/how-to/authenticate) |
| `items` is `[]` but sync said `Done` | Development connector never synced, or the account genuinely has no employees | Re-run Step 5 |
| Empty response right after linking | First sync still running | Poll `sync_status` until `Done` |
| `403` on `/employees` but `/connectors` works | `X-Connector-Token` header missing | Add the second header |
| A field you expected is `null` | Source system doesn't expose it, or the connector doesn't map it | [Why is a field null?](/explanation/field-semantics) |
| `429 Too Many Requests` | 200 req/min per connector exceeded | [Rate Limits](/api-reference/basics/rate-limits) |
