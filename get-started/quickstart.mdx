This is a single tutorial in seven lessons. Work through them in order — each one depends on the state the previous one left behind.

**By the end of this tutorial** you will have employee records from a linked HRIS arriving in your own code, including one field the unified model does not carry, with your application notified when that data changes. About 45 minutes, plus waiting on a sync.

## What you will build

By the end, employee records from a linked HRIS will be arriving in your own code. That includes:

- A **connector** you created and authorized against a test HRIS tenant
- A completed **sync**, and a way to tell when it finished
- **Employee data** read from the Bindbee API in the unified schema
- **One field the unified model does not carry**, mapped out of the raw payload
- A **webhook** telling your application when that data changes

That is the whole thing.

## What you will need

<Info>
  Every item below is something to have open or on hand before lesson 1. If you
  are missing any of them, resolve it first — the lessons assume all five.
</Info>

| You need | How to get it |
| --- | --- |
| Access to the Bindbee Dashboard | Provisioned by the Bindbee team during onboarding. If you cannot sign in, ask in your Slack channel. |
| A **development** environment API key | Dashboard → API Keys, with the environment switcher set to Development. See [Development environment](/how-to/environments/development). |
| Credentials for a test HRIS tenant | Request these in your Slack channel or from [support@bindbee.dev](mailto:support@bindbee.dev). Bindbee hosts sandbox tenants for several systems so you do not have to supply your own. Check [Integrations & Coverage](/integrations) for the supported systems and their slugs — you will need the slug in lesson 3. |
| An HTTP client | `curl`, Postman, or your language's HTTP library. The lessons show `curl` and give you enough to translate. |
| An endpoint that can receive a POST | Needed in lesson 7 only. A local tunnel such as ngrok is fine. |

<Warning>
  Sandbox credentials are not yet self-serve. Request them before you start
  rather than at lesson 3, or the tutorial will stall partway through.
</Warning>

## What this tutorial does not cover

Ruling these out now is what lets every lesson stay a single path with no branching. Each one is a real task — just a later one.

<AccordionGroup>
  <Accordion title="Embedding Magic Link inside your own product">
    In lesson 3 you create a connector from the Dashboard, which is the fastest
    route to a working sync. Embedding the linking flow in your own UI is a
    separate job you will do before you onboard real customers.
  </Accordion>

  <Accordion title="Preparing a real customer's source system">
    Test tenants come with the permissions already granted. Real customers do
    not — and missing permissions are the single most common reason fields
    arrive empty. That is covered in the [Go-live
    checklist](/how-to/go-live-checklist).
  </Accordion>

  <Accordion title="Going to production">
    Everything here happens in the development environment. Moving over is
    covered in [Production environment](/how-to/environments/production),
    including what carries across environments and what does not.
  </Accordion>

  <Accordion title="Writing data back to the source system">
    This tutorial only reads. Bindbee supports writes on several models — see
    the API reference for the endpoints that accept `POST`.
  </Accordion>
</AccordionGroup>

## If you get stuck

Each lesson ends with the failures that lesson can cause. These six account for most of them — worth skimming now so you recognize them when they happen.

| Symptom | Cause | Where it's fixed |
| --- | --- | --- |
| `401 Unauthorized` | Missing the `Bearer ` prefix, or a key from the other environment | [Lesson 1](/get-started/tutorials/set-up-your-environment) |
| `404 Not Found` on a connector endpoint | Connector paths are category-scoped — `/api/hris/v1/connectors`, not `/api/v1/connectors` | [Lesson 1](/get-started/tutorials/set-up-your-environment) |
| `403` on `/employees` while `/connectors` works | The `X-Connector-Token` header is missing | [Lesson 3](/get-started/tutorials/connect-a-test-account) |
| `items` is `[]` and nothing is obviously wrong | Development connectors never sync on their own | [Lesson 4](/get-started/tutorials/run-your-first-sync) |
| A field you expected is `null` | Out of scope, not permitted by the source system, or not carried by the unified model | [How Bindbee decides what data you get](/explanation/what-data-you-get) |
| `429 Too Many Requests` | Per-connector rate limit exceeded | [Rate limits](/api-reference/basics/rate-limits) |
