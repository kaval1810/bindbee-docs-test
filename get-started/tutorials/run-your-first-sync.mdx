A connector with no sync has no data.

**By the end of this lesson** you will have a completed sync and know three ways to tell when one has finished. About 5 minutes, plus the sync itself.

## Context

In production Bindbee syncs on a schedule. In development it does not - you trigger every sync yourself.

<Warning>
  **Development connectors do not sync automatically.** Skip this lesson and
  lesson 5 returns an empty list that looks like a bug. This surprises almost
  everyone once.
</Warning>

## Step 1 - Trigger the sync

From the Dashboard, open your connector info page and choose **Force Sync**. Or from the API:

```bash
curl -X POST https://api.bindbee.dev/api/embedded/v1/connectors/resync \
  --header "Authorization: Bearer $BINDBEE_API_KEY" \
  --header "X-Connector-Token: $CONNECTOR_TOKEN"
```

**Result:** the connector's status changes to `Syncing`.

## Step 2 - Watch it complete

{/* DIAGRAM (tier 2): the sync_status progression a learner sees here - Syncing to Done, with Failed as the third outcome. Keep it small; this is a tutorial and the diagram should reassure rather than teach the whole state model. Link readers to explanation/connector-lifecycle for the connector's own states, which are a different thing from a sync job's. */}

How long depends on the system and how much data the sandbox holds - usually under a few minutes for a test tenant.

Watch it in the Dashboard, or poll the connector list and read `sync_status`:

```bash
curl -G https://api.bindbee.dev/api/hris/v1/connectors \
  --header "Authorization: Bearer $BINDBEE_API_KEY"
```

```json
{
  "items": [
    {
      "id": "018f99e2-ed3a-7f4c-ae97-83d619bdf95c",
      "integration_slug": "breathehr",
      "status": "COMPLETE",
      "sync_status": "Done",
      "last_sync_start_time": "2026-08-07T09:49:22.922083+00:00"
    }
  ]
}
```

Two status fields, and they answer different questions. `status` is the **link** status - `COMPLETE`, `INCOMPLETE`, or `RELINK_NEEDED`. `sync_status` is the **data** status - `Syncing`, `Done`, or `Failed`. A connector can be `COMPLETE` and still have no data, which is exactly the state you were in at the end of lesson 3.

**Result:** `sync_status` reaches `Done`.

## Step 3 - Read the sync logs

Open the **Logs** section and look at the requests Bindbee made to the source system while syncing.

For a model-level view, click into the sync itself. This opens the sync's info page with a breakdown per model, showing whether each one was synced, failed, skipped, or not supported.

Worth doing once on a successful run. It is where you will look first when a real sync misbehaves, and knowing what healthy looks like makes unhealthy obvious.

**Result:** a request-by-request record of the sync you just ran, plus a model-by-model status breakdown.

## What you just did

You have data behind the connector, and three ways to know it arrived:

| Signal | Good for |
| --- | --- |
| `sync_status` shows `Done` in the Dashboard | Watching by hand, right now |
| Polling `sync_status` on the connector endpoint | Scripts and tests |
| A `connector_synced` webhook | Production - your app is told rather than asking |

The third is what you actually want in your product. That is lesson 7.

Once a connector is in production, Bindbee syncs it on a schedule - **once every 24 hours by default**, adjustable by arrangement. If your product needs data sooner than the next scheduled sync, trigger a Force Sync through the API rather than shortening the schedule. See [How syncing works](/explanation/how-syncing-works).

## If this didn't work

<AccordionGroup>
  <Accordion title="Status went to Failed">
    Open **Logs** and find the failing request. The common causes are expired or
    revoked source credentials, and permissions never granted for a model in
    scope. The source system's own error is more informative than the status.
  </Accordion>

  <Accordion title="Sync completed but some models look empty">
    Check scope first - a model you disabled in lesson 2 will not sync. If it is
    in scope and still empty, the source system likely did not grant access.
    Permission problems fail silently: the field is omitted rather than erroring.
  </Accordion>

  <Accordion title="The sync seems stuck in Syncing">
    Large tenants take longer. If it has not moved in well over an hour on a
    sandbox tenant, raise it in your dedicated Bindbee support channel with the
    connector ID, or email [support@bindbee.dev](mailto:support@bindbee.dev).
  </Accordion>

  <Accordion title="Nothing happens when you trigger a force sync">
    A sync already in progress will not be queued twice. Wait for the current one
    to finish.
  </Accordion>
</AccordionGroup>
