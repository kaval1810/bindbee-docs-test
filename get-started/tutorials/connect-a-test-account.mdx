A connector is one customer's authorized link to one source system. Creating one produces the `connector_token` you have been missing since lesson 1.

**By the end of this lesson** you will have an authorized connector and its token.

## Context

In production your customers create connectors themselves through [Bindbee Embed](/how-to/connections/bindbee-embed). Here you create one from the **Dashboard**, which is faster and produces the same result.

You need your own test account for a supported HRIS system before you start to test credentials. If you do not already have one, sign up for a free trial with a supported system.

<Warning>
  This is the one point in the tutorial that can block on getting a test account
  set up. Do that before you continue rather than partway through.
</Warning>

## Step 1 - Create the connector

In the Dashboard, go to **Connectors**, switch to the **Development** tab, and choose **Create connector**. Give the test customer a recognizable organization name such as `Tutorial Test Co`, select category **HRIS**, and pick the integration matching your test account.

**Result:** a connector with status `INCOMPLETE` and a Magic Link.

## Step 2 - Authorize it with your test account

Open the Magic Link. You see what your customer would see: a linking page asking for whatever that system needs - an API key, a subdomain, a client ID and secret, or an OAuth redirect. Enter your test account's credentials and complete every step.

<Info>
  What each system asks for varies. Per-system click-through guides, written for
  your customers rather than for you, live in the
  [Help Centre](https://help.bindbee.dev/guide).
</Info>

**Result:** On successful authorization, the connector's status moves to `ACTIVE`.

## Step 3 - Copy the connector token

Open the connector from the **Connectors** list. On the **Overview** tab, find and copy `connector_token`.

```bash
export CONNECTOR_TOKEN="your_connector_token"
```

**Result:** both halves of the authentication pair are now set in your shell.

## What you just did

You linked one customer to one source system. The Magic Link collected their credentials - Bindbee stores those and in return you got a connector token, which your API calls use to say *whose data*.

The connector hasn't synced yet, so there's no data to read yet.

## If this didn't work

<AccordionGroup>
  <Accordion title="The Magic Link expired">
    Magic Links are time-limited. Regenerate from the connector's page and open
    the new one.
  </Accordion>

  <Accordion title="Authorization failed on the linking page">
    Usually wrong credentials, or a wrong subdomain or company identifier. Check
    **Logs** for the actual error returned by the source system - it is more
    specific than what the linking page shows.
  </Accordion>

  <Accordion title="Connector status stays INCOMPLETE">
    The flow did not finish. Reopen the Magic Link and complete every step -
    several systems have a final confirmation screen that is easy to close early.
  </Accordion>

  <Accordion title="There's no connector_token on the Overview tab">
    Tokens are issued once authorization completes. If the status is still
    `INCOMPLETE`, finish the linking flow first.
  </Accordion>
</AccordionGroup>
