This is a single tutorial in seven lessons - work through them in order, since each one depends on the state the previous one left behind.

**By the end** you will have employee records from a linked HRIS arriving in your own code, including one field the unified model does not carry, with your application notified when that data changes. About an hour of hands-on work, plus waiting on a sandbox signup and a sync.

## What you will build

By the end, employee records from a linked HRIS will be arriving in your own code. That includes:

- A **connector** you created and authorized against a test HRIS integration
- A completed **sync**, with a way to get notified when it finishes
- **Employee data** read from the Bindbee API in the unified schema
- **One field the unified model does not carry**, mapped out of the raw payload using a custom field
- A **webhook** that tells your application when that data changes

That is the whole thing.

## What you will need

<Info>
  Every item below is something to have open or on hand before lesson 1. If you
  are missing any of them, resolve it first.
</Info>

| You need | How to get it |
| --- | --- |
| Access to the Bindbee Dashboard | Provisioned by the Bindbee team during onboarding. If you cannot sign in, email us at [support@bindbee.dev](mailto:support@bindbee.dev) |
| A **development** environment API key | **Settings → API Keys**, from the Development block. See Development environment. |
| Credentials for a test HRIS integration | Sign up for a sandbox or developer tenant with any [supported system](/integrations). Start this before lesson 1 - see the warning below. |

<Warning>
  Of the three, the test HRIS account is the one most likely to cost you real
  time - signing up for a sandbox with a supported system can take longer than
  lessons 1 and 2 combined. Start that signup now if you don't already have
  one, rather than discovering the wait at lesson 3.
</Warning>

## What this tutorial does not cover

Leaving these out keeps each lesson a single path with no branching decisions. They are real tasks - just ones you will handle later.

<AccordionGroup>
  <Accordion title="Embedding Magic Link inside your own product">
    In lesson 3 you create the connector from the Dashboard. Embedding the
    linking flow in your own UI comes later, before you onboard real customers.
  </Accordion>

  <Accordion title="Preparing a real customer's source system">
    Test tenants arrive with permissions already granted. Real customers do not
    - the Go-live checklist covers what to ask for.
  </Accordion>

  <Accordion title="Going to production">
    Everything here happens in the development environment. A production
    connection uses the same steps with a production API key - see Production
    environment.
  </Accordion>

  <Accordion title="Writing data back to the source system">
    This tutorial only reads. For the endpoints that accept `POST`, see the [API
    reference](/api-reference/basics/authentication).
  </Accordion>
</AccordionGroup>

## The lessons

<Steps>
  <Step title="Set up your environment and keys">
    Development versus production, and which of the two tokens goes on which
    request. [Start here →](/get-started/tutorials/set-up-your-environment-and-keys)
  </Step>
  <Step title="Scope the data you need">
    Choose the models and fields your product reads. This decision shapes
    everything downstream. [Lesson 2 →](/get-started/tutorials/scope-the-data-you-need)
  </Step>
  <Step title="Connect a test account">
    Create a connector against a sandbox HRIS tenant and authorize it.
    [Lesson 3 →](/get-started/tutorials/connect-a-test-account)
  </Step>
  <Step title="Run your first sync">
    Development connectors do not sync on a schedule. You will trigger this one
    yourself and watch it complete. [Lesson 4 →](/get-started/tutorials/run-your-first-sync)
  </Step>
  <Step title="Read employee data from the API">
    Your first authenticated call that returns real records.
    [Lesson 5 →](/get-started/tutorials/read-employee-data-from-the-api)
  </Step>
  <Step title="Add a field the unified model doesn't have">
    Find the value in the raw payload, map it, and see it appear on the
    unified object. [Lesson 6 →](/get-started/tutorials/add-a-field-the-unified-model-doesnt-have)
  </Step>
  <Step title="Receive a webhook">
    Subscribe to a webhook so your application stops polling.
    [Lesson 7 →](/get-started/tutorials/receive-a-webhook)
  </Step>
</Steps>
