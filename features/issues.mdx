---

Issues is Bindbee's error tracking for your integrations. When something fails on a connector - a sync, an authorization, a request to the source system - it is raised as an issue rather than left for you to find in the logs.

Each issue records what failed and, where Bindbee can determine it, the likely resolution. Every issue carries the request and response behind it, so you and the Bindbee team are looking at the same evidence when you escalate.

## Where to find it

Open the list of currently open issues from the [Dashboard](/features/dashboard), or open the issues for a single [connector](/features/connectors) from that connector's page. The per-connector view is the faster one when you already know which customer is affected.

## What to do with an issue

Issues tell you *that* something broke and usually *why*. Fixing it happens elsewhere:

| The issue points at | Where it is fixed |
| --- | --- |
| Expired or revoked source credentials | Re-authorize the connector - see [Connectors](/features/connectors) |
| A model failing to sync | [Logs](/features/logs) has the request and the source system's own error |
| A field never arriving | Check [Scoping](/features/scoping) first, then permissions in the source system |
| Errors your own code has to handle | [Handle errors](/how-to/handle-errors) |
